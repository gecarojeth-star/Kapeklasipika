| Date | Decision | Why | Alternatives considered |
|---|---|---|---|
| 2026-10-21 | Use MobileNetV2 with transfer learning | Small and fast enough to run on a phone; pretrained weights work well with only 2,000 images per class | ResNet-18 (used in the original paper, heavier), training a CNN from scratch (needs much more data) |
| 2026-10-21 | Run the model on the phone (TensorFlow Lite) instead of a server | Works offline (useful on farms), no hosting cost, images never leave the device | Server API (FastAPI) — easier to update, but needs internet and hosting |
| 2026-10-21 | Keep the dataset's provided train/val/test split (60/20/20) | Same split the dataset was released with, so results compare fairly with the original paper; balanced classes | Re-splitting ourselves (e.g. 70/15/15) |
| 2026-10-21 | Train on Google Colab instead of the laptop | Laptop has Intel Iris Xe only; TensorFlow trains on CPU there, which is much slower | Laptop CPU training (kept as backup) |
| 2026-10-21 | Normalize pixels inside the model (Rescaling layer), not in the app | The app feeds raw 0-255 pixels, so there's no preprocessing formula to get wrong on the phone | Normalizing in Dart code |
| 2026-10-21 | Augmentation: flips, rotation up to 180°, zoom ±15%, brightness/contrast ±20%, gaps filled with `nearest` | Beans have no fixed orientation; lighting varies on phones. `reflect` filling copied parts of the bean into the corners (seen in the preview), so `nearest` was chosen | No augmentation (risks the paper's overfitting); `reflect` fill |
| 2026-10-21 | Two-stage training: frozen head (lr 0.001), then fine-tune last 40 layers (lr 0.00001), BatchNorm kept frozen | Standard transfer-learning recipe for small datasets; protects pretrained features | Fine-tuning everything from the start |
| 2026-10-21 | Early stopping on validation loss, patience 5, restore best weights | Stops training before overfitting | Fixed number of epochs |
| 2026-10-21 | Center-crop non-square photos before resizing (training and app) | Keeps beans from being stretched; training and phone see images the same way | Squashing the whole photo to a square |
| 2026-10-21 | Real-world phone photos used for testing only | Keeps the real-world score an honest measure of generalization | Mixing them into training |
| 2026-10-21 | Exclude duplicates instead of deleting them: exact copies (keep one), cross-split duplicates confirmed by hash AND pixel check (drop the val/test copy), conflicting-label copies (drop all). List in `02_data/interim/excluded_files.csv` | Notebook 02 found 21 exact copies (the 21 extra files) and 184 hash-flagged pairs, but visual review showed most flagged pairs were different beans (95 even had different labels). A pixel-difference check (≤ 3 of 255) separates true duplicates from look-alikes. Keeps the test score honest without touching raw data | Trusting the hash alone (would wrongly drop ~180 images); ignoring duplicates (inflates test score) |
| 2026-10-22 | Remove exact duplicates by file content (MD5) at load time, in addition to the name list | Notebook 03 showed the name-based list didn't catch the exact copies on Colab (loaded 4,804 / 1,616 instead of 4,800 / 1,599). Content matching works regardless of file names | Fixing names by hand |
| 2026-10-22 | Add experiment 3: extend fine-tuning up to 20 epochs; pick the final model by validation accuracy in notebook 04 | Experiment 2's validation loss was still decreasing at its last epoch, so the model had not converged | Stopping at experiment 2 |
| 2026-10-22 | Drop the real-world phone-photo test; report it as a limitation and future work | No phone photos of green Arabica beans were taken. The core objectives (beat 81.31%, defect-focused evaluation, offline app) don't depend on it | Testing on Robusta or roasted beans (wouldn't be a fair test of an Arabica green-bean model) |
| 2026-10-23 | Add a Mahalanobis-distance "not a bean" detector on MobileNetV2 features (PCA to 64 dims, shared covariance, threshold = 97.5th percentile of validation beans), built into the phone model as a 2nd output | The v1 app labeled a coin Defect at 100%; softmax confidence can't detect unfamiliar inputs. Needs no new training and no non-bean training data; a standard, explainable anomaly-detection method (Lee et al., 2018) | Confidence threshold (fails: the coin scored 100%); training a 5th "other" class (needs a large non-bean dataset) |
| 2026-10-23 | Live scanner: classical bean finder (Otsu threshold + connected components) instead of a trained detector | USK-Coffee has no tray images or boxes to train a detector; beans on a light tray are easy to separate by brightness; runs fast on low-end phones; tested in Python on synthetic trays first | YOLO trained on synthetic composites (1–2 weeks, synthetic-to-real gap) |
| 2026-10-23 | Track beans with IDs (nearest-center matching) and average up to 8 classifications per bean | Stable labels instead of flicker; no double counting; limits work to 2 classifications per frame | Classifying every bean every frame (too slow, labels flicker) |
| 2026-10-23 | Touching beans = blob ≥1.7× median bean area (or long AND ≥1.5×); not classified, counted by area | First rule (elongation ≥2.2 & ≥1.2×) wrongly flagged single longberries on the printed test sheet | Elongation-only rule |
| 2026-10-23 | Weight = bean count × 0.155 g (published 100-bean weight 15.49 g, Urugo et al. 2024) with optional user calibration | A camera cannot weigh; average mass is citable and the user's own calibration is more accurate | Estimating mass from bean area (needs a known scale and density; unreliable) |
| 2026-10-23 | Test the live scanner with printed sheets of test-set beans | No real green beans available; true labels are known, so live accuracy can be measured | Untestable without beans |
